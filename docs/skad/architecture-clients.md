## Why it matters beyond being a terminal client

**`tui/` is the reference proof that the Gateway contract is client-agnostic.** It speaks the same
protocol as the React app with one dependency and no framework, and it reuses the *same* protocol
modules rather than reimplementing them:

```js
new URL('/api/realtime', baseUrl)            // same socket path as web
GatewayClient                                 // shared/gateway-client-sdk.mjs
reduceGatewayClientState                      // shared/gateway-client-state.mjs — same reducer
clientInputCapabilities                       // shared/client-input-capabilities.mjs
gatewayReferenceClientCapabilities            // shared/gateway-client-profiles.mjs
formatCitationLines                           // shared/citation-display.mjs
```

When adding a new client, this is the model to copy: take the reducer and the SDK from `shared/`,
supply your own I/O.

## Audio architecture

Voice I/O is **out-of-process**, via two native helpers in `tui/native/`:

| Helper | Language | Platform |
| --- | --- | --- |
| `macos-voice-io.swift` | Swift | macOS — AEC-capable |
| `portaudio-voice-io.py` | Python | Cross-platform PortAudio |

| Env var | Default | Meaning |
| --- | --- | --- |
| `QWEN_AUDIO_AGENT_TUI_AUDIO_MODE` | `'half'` | Half-duplex by default |
| `QWEN_AUDIO_AGENT_TUI_AEC_BINARY` | — | Path to the macOS AEC binary |

**Half-duplex is the default for a reason**: a terminal without echo cancellation will feed the
model its own output. Full duplex is opt-in and expects the AEC binary. `tui/native/` is excluded
from ESLint.

## The zero-dependency constraint

This is a deliberate architectural decision, not an accident: `qwenaudio` is the published install
surface, and having no runtime dependencies keeps it installable in any environment without
resolution conflicts. **Adding a dependency here changes the product's install story** — reach for
`shared/` instead (the CLI already imports 5 modules from it).

## Module map

| Module | LOC | Role |
| --- | --- | --- |

## Compatibility gates

`runtime.mjs` exports three checks that run **before** the CLI does work:

| Function | Guards |
| --- | --- |
| `assertGatewayCompatibility(health, backend)` | The running Gateway supports the requested backend |
| `assertRealtimeGatewayCompatibility(health, env)` | The Gateway supports the requested realtime configuration |
| `waitForGateway(baseUrl, …)` | Polls readiness instead of racing a cold start |
| `isLocalGateway(baseUrl)` | Local vs. remote branching |

These read `GET /api/health` — which is why that endpoint echoes `gatewayInstanceId` and the
capability list. `ManagedRuntime` / `ensureRuntime()` own starting a Gateway if one is not already
up, arbitrated by `shared/gateway-instance-lock.mjs`.

## OS service integration

`gateway-service.mjs` registers the Gateway as a managed OS service under the label
`com.qwen-audio-agent.gateway` (`gatewayServiceDefinition()`, `manageGatewayService(action)`) — how
the Gateway survives logout and restarts.

## Configuration surface

`config-command.mjs` validates against a known-model list (`assertKnownRealtimeModel`) and, after a
successful write, emits `GATEWAY_RESTART_FOLLOW_UP`: *the configuration changed; run
`qwenaudio gateway restart` for the Gateway to pick up the new model.* Model changes are **not**
hot-reloaded.

# shared — the contract layer ◆

| | |
| --- | --- |
| Package | none — no `package.json` of its own |
| Type | `library` |
| Files | 43 tracked |
| Consumed by | 64 files across all 6 workspaces, plus third-party extensions |
| Published as | ~20 of the root package's 42 `exports` entries |

## The rule

> **`shared/` has no inbound dependency on any part. Every part depends on it. Every change to it is
> a public API change.**

It is not a utility folder. It is the published contract between the Gateway, its first-party
clients, and third-party extensions, and it is the only directory where "just rename this" is never
safe.

## Composition

| Group | Modules | Notes |
| --- | --- | --- |
| Protocol & events | 5 | `gateway-client-protocol.mjs` (26 zod envelopes, GCP6 v6.0.0), `realtime-events.mjs` (15 + 22 enums), `session-events.mjs`, `protocol/gateway-events.mjs`, `protocol/agui-events.mjs` |
| Client SDK | 7 | `gateway-client-sdk.mjs`, `gateway-client.mjs`, `gateway-client-state.mjs` (the pure reducer), `gateway-client-profiles.mjs`, `client-input-capabilities.mjs`, `conversation-history.mjs`, `conversation-session.mjs` |
| Remote access & auth | 7 | `gateway-remote-access.mjs`, `gateway-access-client.mjs`, `gateway-websocket-auth.mjs`, `gateway-file-credential-store.mjs`, `gateway-connection-profiles.mjs`, `gateway-endpoint-publishers.mjs`, `gateway-tailscale-publisher.mjs` |

| Backend lifecycle | 7 | `backend-{catalog,environment,install,lifecycle,onboarding,setup,auth-status}.mjs` |
| Runtime utilities | 12 | `file-transaction-lock.mjs`, `runtime-crypto.mjs`, `runtime-environment.mjs`, `path-environment.mjs`, `process-path.mjs`, `orb-skin-catalog.mjs`, `realtime-{model,provider}-catalog.mjs`, `input-parts.mjs`, `citation-display.mjs`, `skill-library.mjs`, `logger.mjs` |

## Design characteristics

- **Environment-neutral.** `runtime-crypto.mjs` and `runtime-environment.mjs` exist so the same
  module runs under Node, a browser, and Capacitor. `mobile/` and `web/` import the same files the
  server does.
- **Pure where it can be.** `gateway-client-state.mjs` is a pure reducer with no I/O — which is why
  React (`useReducer`) and the TUI (plain calls) can both use it.
- **Catalogs are data, not logic.** `orb-skin-catalog.mjs`, `realtime-model-catalog.mjs`, and
  `realtime-provider-catalog.mjs` are validated lookup tables shared by server, web, and desktop, so
  a skin or model id means the same thing everywhere.
- **`.cjs` where required.** `electron-host.cjs` is CommonJS because an Electron preload context
  requires it.

## Testing

`shared/` has no test directory of its own. It is covered transitively by the parts that import it
and by `test/` at the repo root — **so a `shared/` change is only as well-tested as its consumers**,
and third-party consumers are not tested here at all.

## smart-cockpit topology

```
npm run example:smart-cockpit
  └─ preflight (bootstrap/preflight.mjs)
  └─ concurrently --kill-others-on-fail:
       service   examples/smart-cockpit/service/server.mjs
       agent     examples/smart-cockpit/agent/server.mjs
       gateway   examples/smart-cockpit/gateway/server.mjs
       client    vite dev
```

`--kill-others-on-fail` means one process dying stops the set, rather than leaving a half-running
system. `preflight.mjs` validates the environment before any process starts.

## Dependency isolation

Examples are deliberately **not** workspaces:

```bash
npm run example:smart-cockpit:install   # npm install --prefix into 3 subprojects
npm run test:smart-cockpit              # pretest: npm ci --ignore-scripts, then 4 test dirs
npm run test:voicemem
```

`--ignore-scripts` in the test hook means example dependencies cannot run install scripts in CI.
Both example suites do run as part of the root `npm test`, so **a broken example fails the build** —
they are maintained code, not sample snippets.
