## Executive summary

`server/` is **the Gateway**: a local Node process that holds a realtime voice conversation with the
user while delegating longer work to a separate background agent, then narrates the results back.
It is 308 tracked files across 16 domains — the largest part by a wide margin.

The product claim it implements: *keep the agent talking while work continues.* Almost every
non-obvious design decision in this part follows from that — turn correlation, announcement
batching, playback receipts, input arbitration, and owner takeover all exist because **voice runs
concurrently with background work rather than blocking on it.**

## The architectural boundary that governs everything

`CONTRIBUTING.md` states it as the first change principle:

> **Preserve the boundary between the Realtime frontend and the background Agent.**
> (`docs/architecture/deep-dive.md`)

Concretely:

| Realtime frontend (`voice/`, `frontend/`, `conversation/`) | Background agent (`agent/`, `backend/`, `process/`, `task/`) |
| --- | --- |
| Owns the conversation, the voice provider socket, turn state, transcripts | Owns delegated work, backend adapters, subprocess lifecycle |
| Latency-critical | Long-running |
| Speaks GCP6 to clients | Speaks ACP / A2A to agents |
| Never blocks on backend work | Reports progress as events, never as a blocking call |

`task/` and `delivery/` are the seam. **Code that makes the voice path await backend completion
violates the boundary**, even when it appears to simplify.

## Architecture pattern: domain-partitioned service with a single composition root

Not layered, not hexagonal-by-the-book, not microservices. Sixteen sibling domains under
`server/src/`, wired together in exactly one place.

### Composition root

```
bootstrap.mjs                            ← 9 lines: createGatewayApplication(), re-export
   └── gateway-application.mjs           ← the ONLY place domains are wired
         ├── constructs ~30 services (IdentityManager, FrontendMemoryService,
         │   DomainLibrary, GatewayAccessManager, BackendWorkRuntime,
         │   PreferenceCandidatePool, SessionDigestPool, …)
         ├── registers all 28 route handlers (27 addressable + `GET *` catch-all)
         └── returns { app, server, services, start, close }
```

`bootstrap.mjs` is deliberately trivial. **All wiring lives in `gateway-application.mjs`**, which
means it is long — but it also means there is exactly one file to read to learn what the Gateway is
made of, and one place where a new domain gets connected.

`services` is returned from the factory, so tests construct the whole application and reach in,
rather than mocking module graphs.

### Dependency injection by default parameter

The prevailing idiom is `import { config as defaultConfig }` / `logger as defaultLogger` /
`agent as defaultAgent` and then accepting an override:

```js
createGatewayApplication({ config = defaultConfig, logger = defaultLogger, ... } = {})
```

Production gets the module singleton; tests pass a substitute. **Follow this rather than importing
a singleton directly inside a domain** — it is what keeps the suite runnable without a live backend.

## API design

27 addressable HTTP routes plus a `GET *` catch-all (28 Express registrations) and one WebSocket, all registered in `app/gateway-application.mjs`. Full catalog in
[`api-contracts-server.md`](./api-contracts-server.md).

### Capability-based versioning

`core/gateway-protocol.mjs` freezes `GATEWAY_CAPABILITIES` — 29 strings — alongside
`GATEWAY_PROTOCOL_VERSION` 5.7.0. Clients branch on a capability, never a version. Minor bump for
an additive capability, major for a breaking change to anything listed; **every capability is locked
by a test**, and anything unlisted is internal.

### Middleware ordering is a security boundary

```
express.json({ limit: '1mb' })            line 538
GET  /connect                             line 543   ← pre-auth (HTML pairing shell)
POST /api/access/pair                     line 554   ← pre-auth (origin-allowlisted)
──────────────────────────────────────────────────
app.use(…)                                line 583
app.use(enforceSameOrigin)                line 598   ← everything below is authenticated
app.use(…)                                line 599
```

> **A route added above line 598 is public.** This ordering is load-bearing and easy to break with
> an innocuous-looking insertion.

## Data architecture

**No database.** Six versioned JSON snapshot stores with atomic writes, `0600` permissions,
corruption quarantine, and degrade-never-crash semantics. Every store accepts `filePath = null` for
memory-only operation. Wire validation is `zod`, distinct from persistence.

Full detail — including the mandatory `fileVersion` bump rule — in
[`data-models.md`](./data-models.md).

## Event architecture

Three vocabularies, one canonical source:

```
backend events (core/backend-events.mjs, normalized by the adapter)
   └─▶ Gateway task events (20)
         ├─▶ GCP6 task events        → clients, default WS stream
         ├─▶ AG-UI ACTIVITY_SNAPSHOT → GET /api/tasks/:id/events?format=ag-ui
         └─▶ session journal          → GET /api/sessions/:id/replay (bounded)
```

Realtime vocabulary is separate: 15 client→server and 22 server→client events
(`shared/realtime-events.mjs`), plus 26 GCP6 zod envelope schemas.

Projections are added as projectors (`transport/*-projector.mjs`) without changing the canonical
event. Backpressure — concurrency caps, TTLs, announcement batching and retry — is configured by
environment variable rather than hard-coded.

## Development workflow

```bash
npm run dev                    # server + web concurrently
npm run gateway                # pregateway builds web/, then starts the Gateway
npm test --workspace server    # node --test
npm run eval:frontend          # server/eval/run-frontend-evaluations.mjs (not in npm test)
```

`server/` has `test/`, `fixtures/`, and `eval/` beside `src/`. No transpilation, so a restart is the
full edit cycle.

## Deployment architecture

**A local process on the user's machine.** No Dockerfile, no Kubernetes, no IaC. Started by the
CLI, the desktop app, or `scripts/start.mjs`, arbitrated by `shared/gateway-instance-lock.mjs`, and
optionally registered as an OS service (`com.qwen-audio-agent.gateway`).

Remote reach is a **Tailscale HTTPS tunnel to that same local process**, with paired per-device
tokens — not a hosted deployment. `GET /api/health` echoing `gatewayInstanceId` exists precisely
because several processes may contend for one port.

## Testing strategy

`node --test` only, suites in `server/test/` with fixtures in `server/fixtures/`. The two structural
enablers:

1. **Factory + injected defaults** — `createGatewayApplication({ config, logger, agent })` lets a
   test build the real application with substitutes.
2. **`backend-adapter-conformance.mjs`** — a reusable conformance suite so every adapter, including
   third-party ones, is verified against the same `BackendPort` contract rather than each writing
   its own ad-hoc checks.

Plus: every one of the 29 capabilities is locked by a test, which is what makes the
capability-negotiation scheme trustworthy.
