**Declared workspaces:** `server`, `web`, `tui`, `desktop`, `cli`, `mobile`.
`shared/` and `examples/` are *not* workspaces — `shared/` is reached through the root package
`exports` map, and `examples/` install their own dependencies.

## The dependency direction that matters

```
                         ┌──────────────┐
                         │   shared/    │ ◆ the contract layer
                         └──────┬───────┘
              ┌─────────┬───────┼────────┬─────────┐
              ▼         ▼       ▼        ▼         ▼
          server/     web/    tui/     cli/    examples/
                        ▲
              ┌─────────┴─────────┐
              │                   │
          desktop/             mobile/
       (loads web/dist      (imports web/src/App.jsx
        via ?desktop=orb)    at runtime)
```

Two consequences that are easy to miss:

1. **`web/` is not a leaf.** Desktop and mobile both render it. A change to `web/src/App.jsx` ships
   to all three clients. This is why `.github/workflows/mobile.yml` triggers on `web/**`.
2. **Everything depends on `shared/`, and nothing in `shared/` depends on a part.** It is the only
   directory with no inbound coupling to worry about — and the only one where a change is
   automatically a public API change.

### Reading the server

Start at `app/bootstrap.mjs` → `app/gateway-application.mjs`. The 16 domains are composed there;
none of them import each other's internals through deep paths in normal use.

**Domain size is a signal.** `voice/` (42) and `agent/` (33) hold 24% of the repo's tracked files
between them — they are the product. `access/` and `delivery/` (2 each) are thin boundaries.
