**There is no message queue, no shared database, and no service mesh.** Every integration is either
a WebSocket, an HTTP call, a child process speaking a protocol over stdio, or a direct ESM import.

## ① The client↔Gateway contract

**One socket per client, carrying everything.** Tasks, permissions, conversation history, and voice
all multiplex over `/api/realtime` — even where an equivalent REST route exists. The REST routes
serve tooling and non-socket clients; the first-party UIs use the socket.

### Versioning

| Constant | Value | Meaning |
| --- | --- | --- |
| `GATEWAY_PROTOCOL_VERSION` | 5.7.0 | Gateway protocol |
| `GATEWAY_CLIENT_PROTOCOL_VERSION` | 6.0.0 | GCP6 client protocol |
| `GATEWAY_CAPABILITIES` | 29 frozen strings | The compatibility surface |

> **Clients branch on a capability string, never on a product version.** Minor bump for an additive
> capability; major bump for a breaking change to anything in `GATEWAY_CAPABILITIES`. Anything not
> listed is internal. Every listed capability is locked by a test.

This is what lets a new first- or third-party client connect without a Gateway allowlist entry —
`clientDescriptor()` treats `clientType` as **descriptive metadata only**, and runtime behavior is
negotiated from capabilities.

### Handshake and ownership

```
client                                  server
  │── session hello (capabilities) ──────▶│
  │◀───── session ready ──────────────────│  capability ...v6-handshake
  │                                       │
  │── input / voice / commands ──────────▶│
  │◀──── events, transcripts, audio ──────│
  │                                       │
  │◀──── voice.ownership / deactivated ───│  capability ...v6-owner-takeover
```

Multiple clients may attach to one session. `active-client-leases.mjs` and
`gateway-client-replay-buffer.mjs` implement **owner takeover with replay**: a second client taking
the microphone receives buffered history rather than an empty view. Each client identifies itself
with a per-instance `crypto.randomUUID()`, so two browser tabs are distinct owners.

### Audio format

| Direction | Rate | Encoding |
| --- | --- | --- |
| Client → Gateway | 16 kHz | base64 PCM |
| Gateway → Client | 24 kHz | base64 PCM |

Resampling happens client-side (`web/src/audio.js`).

### Playback receipts — a cross-part invariant

Clients acknowledge playback start and end. The Gateway treats a missing receipt as failed playback
and retries. This is why `desktop/src/orb-window.mjs` and `main.mjs` set
`backgroundThrottling: false`: an unfocused orb window with throttled timers would delay receipts
and trigger spurious retries. **A client-side change that delays receipts is a protocol bug, not a
UI bug.**

## ② Authentication flow across parts

```
LOCAL                                REMOTE
─────                                ──────
web ──── same origin ────▶ Gateway   mobile ── scan QR ──▶ invitation (URL fragment)
        zero config                     │
                                        ├─ POST /api/access/pair  ← only unauthenticated
                                        │     { code, device:{id,type,label} }   remote op
                                        │
                                        ◀─ { access_token, device:{id} }
                                        │
                                        ├─ store in Keychain/Keystore (SecureStorage)
                                        │
                                        └─ WS: token as subprotocol, wss: enforced
                                           HTTP: Authorization: Bearer
```

Enforced properties:

- The invitation lives in the **URL fragment**, so it never appears in a request or an access log.
- `POST /api/access/pair` is registered **before** the auth middleware (line 554, vs. 583–599) — it
  is the sole pre-auth remote route, and is guarded by an origin allowlist for browsers.
- Tokens are stored **hashed** in `GatewayDeviceRegistry`, so revocation works without the Gateway
  holding the credential.
- **Secrets never travel inside GCP messages** — only in the subprotocol or an HTTP header.
- Remote transport is Tailscale HTTPS to the user's own machine, not a hosted service.

## ③ The Gateway↔backend boundary — `BackendPort`

The most important extension seam in the system. `server/src/backend/backend-port.mjs` defines a
**protocol-neutral** port with exactly ten methods:

```
describe()   start(ctx?)   health()   submit(task, ctx?)   status(taskId?, ctx?)
cancel(taskId, ctx?)   respondAuthorization(taskId, authId, decision, ctx?)
respondInput(taskId, inputRequestId, response, ctx?)   subscribe(listener)   close()
```

### The rule that makes this work

> **Every adapter exposes the complete method surface. Optional behavior is advertised by
> `describe()` and rejected explicitly by the adapter — callers never infer support from a missing
> method.**

`assertBackendPort()` enforces this at construction, throwing `BackendPortContractError`
(`code: 'INVALID_BACKEND_PORT'`) listing the missing methods. Duck-typing a partial adapter fails
fast rather than at runtime. `backend-adapter-conformance.mjs` provides the conformance suite.

### Implementations

| Adapter family | Transport | Modules |
| --- | --- | --- |
| ACP (13 backends) | subprocess over stdio, `@agentclientprotocol/sdk` | `agent/backends/{claude,codex,opencode,openclaw,pi,codebuddy,deepseek-harness,generic-acp,local-acp,private-file,…}.mjs` |
| A2A | HTTP JSON-RPC **or** REST, auto-selected | `backend/a2a-backend-adapter.mjs` |
| Custom | anything | `backend/backend-adapter-sdk.mjs` ◆ published |

The A2A adapter uses `DefaultAgentCardResolver` with `JsonRpcTransportFactory` and
`RestTransportFactory`, polls at 1 s (`DEFAULT_POLL_INTERVAL_MS`), uses a 30 s request timeout, no
overall task timeout by default, and caps payloads at 1,000,000 chars / 32 artifacts / 64 artifact
parts. Default output modes: `text/plain`, `text/markdown`.

Adapters emit **normalized backend events** (`core/backend-events.mjs`) through `subscribe()`, so
the Gateway never sees adapter-specific event shapes.

## ④ Event projection — one source, three vocabularies

```
backend events ──▶ Gateway task events ──┬──▶ GCP6 task events   (default WS stream)
                                          ├──▶ AG-UI ACTIVITY_SNAPSHOT
                                          │      GET /api/tasks/:id/events?format=ag-ui
                                          │      capability tasks.ag-ui-event-stream
                                          └──▶ session journal ──▶ bounded replay
                                                 GET /api/sessions/:id/replay
```

Projectors: `transport/agui-event-projector.mjs`, `transport/gateway-task-event-projector.mjs`.
Journal and replay: `session/session-journal.mjs` ◆, `session/session-replay.mjs` ◆.

Adding `?format=ag-ui` leaves the default stream unchanged — this is the pattern for new
projections: add a projector, do not alter the canonical event.

## ⑤ Intra-repo coupling via `shared/`

64 files import `shared/`. The coupling is **compile-time ESM**, not network, which means:

- A `shared/` change breaks parts at import time, caught by `npm test` — but only for parts covered
  by the suite in `npm test`'s sequence.
- Because `shared/` is published through 42 `exports` entries, the same change breaks third-party
  extensions **silently**, with no test in this repo to catch it.

| Part | Files importing `shared/` | What they take |
| --- | --- | --- |
| server | 32 | Protocol, events, credential store, file locks, catalogs |
| desktop | 14 | Orb skin catalog, session normalization, gateway process/lease, electron host |
| web | 8 | Events, client SDK, state reducer, capabilities, WS auth |
| cli | 5 | Gateway process, setup, instance lock, skill library, runtime env |
| tui | 3 | Events, state reducer, client SDK, input parts, citation display, logger |
| mobile | 2 | Remote access, runtime crypto |

`tui/` is the cleanest demonstration of the client contract: `tui/src/index.mjs` connects to
`new URL('/api/realtime', baseUrl)` with `ws`, and reuses `GatewayClient`,
`reduceGatewayClientState`, `clientInputCapabilities`, and `gatewayReferenceClientCapabilities` —
**the same reducer the React app uses**. A new client is expected to do the same rather than
reimplement protocol state.

## ⑥ Gateway process lifecycle

Three parts can start a Gateway, and they must not fight over one:

| Starter | Module |
| --- | --- |
| `cli/` | `gateway-service.mjs`, `launcher.mjs`, `instance-lock.mjs` |
| `desktop/` | `gateway-process.mjs`, `graceful-shutdown.mjs` |
| `scripts/start.mjs` | direct launch |

`shared/gateway-instance-lock.mjs` ◆ (`./gateway-lease`) arbitrates. The companion runtime check is
`GET /api/health`, which echoes `gatewayInstanceId` — capability `gateway.instance-lease` exists so
a client can confirm it reached **this** Gateway and not a foreign process that happens to hold the
same port. Error codes `QWAUDIO_GATEWAY_ALREADY_RUNNING` and `QWAUDIO_GATEWAY_SETUP_REQUIRED`
surface the two failure modes.

## Data flow — one voice turn end to end

```
1  microphone ──▶ web/src/microphone-capture.js ──▶ resample 16 kHz ──▶ pcmBase64
2  ──▶ WS /api/realtime ──▶ voice/realtime-gateway.mjs
3  ──▶ voice/input-arbitration.mjs      (does this client own the mic?)
4  ──▶ voice/providers/*                (DashScope / S2S / OpenAI-compatible)
5  ──▶ transcript ──▶ VOICE_STATE / TURN_STARTED events ──▶ all attached clients
6  model decides to delegate ──▶ task/task-manager.mjs ──▶ BackendPort.submit()
7  backend events ──▶ task events ──▶ projected ──▶ clients + session journal
8  response audio 24 kHz ──▶ base64 ──▶ client playback ──▶ playback receipt ──▶ Gateway
```

Steps 5 and 8 are where the **stale-turn guard** and the **playback ledger** live —
`acceptsGatewayVoiceState()` in `shared/gateway-client-state.mjs` and `playbackRef` in
`useRealtimeVoice.js`. Both exist because steps 5–8 are concurrent with a new turn starting.
