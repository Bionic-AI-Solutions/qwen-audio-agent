## Transport layer

All network access funnels through one module — `web/src/gateway-transport.js` — which holds a
frozen module-level `runtime` record configured once at boot by `configureGatewayTransport()`:

| Field | Purpose |
| --- | --- |
| `gatewayUrl` | Remote Gateway origin, or `''` for same-origin |
| `accessToken` | Bearer/paired-device credential, or `''` for local zero-config |
| `clientType` | Descriptive client identity (default `web`) |
| `clientLabel` | Human label (default `WebUI`) |

### Enforced invariants

These are validated in `cleanGatewayUrl()` and `createGatewayWebSocket()` and are worth knowing
before touching this file:

- **A Gateway URL must be an origin.** `http:`/`https:` only, and any path, query, fragment,
  username, or password throws `TypeError`. This prevents a pairing payload from smuggling a path.
- **Credentials require `wss:`.** If `gatewayWebSocketProtocols(accessToken)` yields any protocol
  (i.e. a token exists) and the socket URL is not `wss:`, the constructor throws
  `Remote Gateway credentials require a secure WebSocket endpoint`. A token can never cross plain `ws:`.
- The token is carried as a **WebSocket subprotocol**, not a query parameter — so it stays out of
  URLs and access logs. Over HTTP it becomes an `Authorization: Bearer` header.
- `gatewayFetch` always sets `credentials: 'include'`.

### URL construction

| Function | Produces |
| --- | --- |
| `gatewayHttpUrl(path)` | `path` resolved against `gatewayUrl`, or returned as-is when same-origin |
| `gatewayRealtimeUrl(sessionId)` | `ws(s)://<host><basePath>api/realtime?sessionId=<encoded>` |
| `gatewayWebSocketProtocols(token)` | Subprotocol list carrying the credential (from `shared/`) |

Note `gatewayRealtimeUrl` derives its base path from `location` when same-origin, so the Web UI
keeps working when the Gateway serves it from a sub-path.

> **Note:** everything else — tasks, permissions, conversation history — is *not* fetched over
> REST by the Web UI. It goes over the WebSocket as a request/response pair (see below), even
> though equivalent REST routes exist on the server. Adding a REST call where a GCP command already
> exists would fork the contract.

### Input queueing and the manual-input guard

`sendInput` is the one place with non-obvious lifecycle behavior:

1. `holdManualInputGuard()` sets a pending flag with a **30 s** `setTimeout` auto-release.
2. If the socket is `OPEN`, send immediately; on send failure the guard is released and `false` returned.
3. If the socket is not open but `hasConnectedRef` is true (a reconnect is in flight), the event is
   **buffered** in `pendingManualInputsRef` and flushed by `flushPendingManualInputs()` on reconnect.
4. If it has never connected, the guard is released and the send reported as failed.

The guard exists so microphone samples captured while a typed message is in flight are suppressed
(`microphoneSamplesDuringManualInput`) and released by `releasesManualInputGuard(event, turnId)`.
Removing the timeout would strand the microphone if the release event never arrives.

## Audio contract

| Constant | Value | Meaning |
| --- | --- | --- |
| `DEFAULT_INPUT_RATE` | `16000` | Microphone capture rate sent to the Gateway |
| `OUTPUT_RATE` | `24000` | Playback rate for returned audio |

`web/src/audio.js` provides `decodePcm`, `pcmBase64`, and `resample` — audio crosses the socket as
**base64 PCM**, resampled client-side to the rates above.
