## Deployment model: there is no server to deploy

The scan found **no `Dockerfile`, `docker-compose.yml`, `k8s/`, `helm/`, `terraform/`, or
`pulumi/`** anywhere in the repository. This is not an omission.

> **The Gateway is a process on the user's own machine.** It is *distributed*, not *deployed*.

Everything that would normally be infrastructure is instead a local-process concern:

| Normally infrastructure | Here |
| --- | --- |
| Load balancer / ingress | `shared/gateway-instance-lock.mjs` arbitrates one local port |
| Service discovery | `GET /api/health` echoes `gatewayInstanceId` |
| TLS termination | Tailscale HTTPS to the user's own machine |
| Auth service | Per-device paired tokens, hashed in a local JSON file |
| Database | Versioned JSON snapshots on local disk |
| Process supervisor | OS service `com.qwen-audio-agent.gateway`, or the desktop app |

This shapes the security model: remote access means **tunnelling to the user's machine**, which is
why `mobile/` refuses any Gateway URL that is not `https:` and why the pairing invitation travels in
a URL fragment.

## Release pipeline

Release is **changelog-driven**. Nothing publishes unless the version changes.

```
1  branch:  release/0.11.0  (or codex/release-0.11.0)
2  npm run version:{patch|minor|major}       syncs root + 6 workspaces + package-lock.json
3  edit CHANGELOG.md                          required — the workflow verifies it
4  npm run release:check                      local gate
5  open PR → merge to main
6  release.yml:  verify version changed
                 verify CHANGELOG entry exists
                 verify full checks pass
                 → tag v0.11.0
                 → npm publish (provenance)
                 → build Universal macOS, sign, notarize
                 → upload DMG to the GitHub Release
```

**A normal PR merge, or any `main` push that does not change the version, publishes nothing.**

### `npm run release:check` — what it actually verifies

`scripts/release-check`:

1. The root `package.json` version is valid semver (including prerelease/build metadata).
2. **All seven manifests carry that exact version** — root, `server`, `web`, `tui`, `desktop`,
   `cli`, `mobile`. A drifted workspace version fails the release.
3. `README.md` and `README_ZH.md` both use the dynamic npm badge
   (`img.shields.io/npm/v/qwen-audio-agent`) rather than a hard-coded version.

Use `npm run version:*` rather than editing manifests by hand — `scripts/set-version.mjs` is what
keeps those seven files in agreement.

### Recovering an interrupted release

If the workflow dies between tagging, npm upload, and Release creation:

> Re-run the **Release** workflow manually from GitHub Actions with the current `package.json`
> version as the `version` input. **Stages that already completed are safely reused.**

## CI workflows

All four declare `permissions: contents: read`, pin actions by commit SHA, set
`persist-credentials: false`, and use a concurrency group.

| Workflow | Trigger | Jobs |
| --- | --- | --- |
| `ci.yml` | push to `main`, all PRs | `test`: {ubuntu, macos, windows} × Node {22.22.2, 24.15.0}, `fail-fast: false` → 6 jobs; plus release-check |
| `docs.yml` | path-filtered: `docs/**`, `scripts/sync-docs-site.mjs`, manifests | VitePress build on Node 22.22.2 |
| `mobile.yml` | path-filtered: `mobile/**`, **`web/**`**, `shared/**`, manifests | `android` (ubuntu), `ios` (macos) |
| `release.yml` | `main` push touching `CHANGELOG.md` or any manifest; or `workflow_dispatch` | plan → verify → tag → npm → platform artifacts. `cancel-in-progress: false` |

`mobile.yml` triggering on `web/**` is correct and load-bearing: mobile embeds the web client, so a
web change is a mobile change.

Only `release.yml` sets `cancel-in-progress: false` — a partially cancelled release is worse than a
queued one.

## Building desktop artifacts locally

```bash
npm run desktop:build:local     # unsigned macOS DMG — use this for local iteration
npm run desktop:build           # signed + notarized; FAILS without release credentials
npm run desktop:build:linux     # AppImage + deb
npm run desktop:build:win       # Windows x64, --publish never
npm run test:desktop-smoke      # scripts/electron-smoke.mjs
```

`desktop:build` runs `scripts/check-desktop-release-env.mjs` first, so it fails fast with a clear
message rather than partway through a build. `desktop:build:local` overrides
`mac.identity=-`, `hardenedRuntime=false`, `notarize=false`.

Packaging config: `desktop/electron-builder.yml`, entitlements in `desktop/build/`.

## Mobile builds

```bash
npm run mobile:build     # vite build → mobile/dist
npm run mobile:sync      # build + cap sync into ios/ and android/
npm run mobile:ios       # sync + open Xcode
npm run mobile:android   # sync + open Android Studio
```

`cap sync` copies the web bundle into `mobile/ios/App/App/public/` and
`mobile/android/app/src/main/assets/public/` — both are ESLint-ignored because they hold generated
output. Do not edit them.

App identity: `com.qwenaudio.agent` / "Qwen Audio Agent", hostname `qwaudio.local`, with
`iosScheme` and `androidScheme` both `https`.

## Documentation site

```bash
npm run docs:dev        # predocs:dev  → sync-docs-site.mjs --watch, then vitepress dev
npm run docs:build      # predocs:build → sync, then vitepress build
npm run docs:preview    # predocs:preview → sync, then vitepress preview
```

`scripts/sync-docs-site.mjs` materializes `docs/.vitepress/.site/` from the side-by-side bilingual
tree: `page.md` → `<path>/page.md`, `page.zh.md` → `zh/<path>/page.md` with relative `.zh.md` links
rewritten. Assets are mirrored into both trees.

### ⚠ The parity rule bites hard

```js
if (missingPairs.length) {
  throw new Error(`Published documentation must be bilingual:\n${...}`)
}
```

**Every `.md` under `docs/` must have a `.zh.md` companion, or the sync throws — and it runs as a
`pre` hook on all three `docs:*` scripts.** An English-only page does not degrade the site; it
breaks the build.

Escape hatches, both in `scripts/sync-docs-site.mjs`:

| Set | Current members |
| --- | --- |
| `EXCLUDED_DIRS` | `promo`, `roadmap`, `skad`, `node_modules` |
| `EXCLUDED_FILES` | `i18n-parity.md`, `frontend-agent-roadmap.md`, `voice-agent-architecture-presentation.zh.md` |

> **`skad` was added to `EXCLUDED_DIRS` by this documentation run.** Before that change,
> `node scripts/sync-docs-site.mjs` failed with 15 missing-pair errors, breaking `npm run docs:build`
> and the `docs.yml` workflow, because `docs/skad/` holds English-only internal scan output. After
> the change the sync materializes 87 files normally.
>
> If SKAD output is ever moved out of `docs/`, that exclusion can be removed. If more English-only
> internal directories are added under `docs/`, they need the same treatment.

Site config lives in `docs/.vitepress/config.mjs` (`srcDir: '.vitepress/.site'`).

## Runtime deployment on a user machine

| Step | Mechanism |
| --- | --- |
| Install | `npm i -g qwen-audio-agent`, or a platform installer |
| Configure | `.env` / `config.env` — `DASHSCOPE_API_KEY` at minimum; `qwenaudio config` for the model |
| Start | `qwenaudio`, the desktop app, or `npm start` |
| Supervise | OS service `com.qwen-audio-agent.gateway` (`cli/src/gateway-service.mjs`) |
| Single instance | `shared/gateway-instance-lock.mjs`; failure code `QWAUDIO_GATEWAY_ALREADY_RUNNING` |
| First-run gate | `QWAUDIO_GATEWAY_SETUP_REQUIRED` until configuration exists |
| Remote access | Enable in desktop settings → mint invitation → pair a device over Tailscale HTTPS |
| Revoke | `DELETE /api/access/devices/:id` |

Config and data directories are `QWAUDIO_CONFIG_DIR` / `QWAUDIO_DATA_DIR`; the desktop app requires
an explicit `configDir` and creates it `0700` with files `0600`.

Model changes are **not** hot-reloaded — `qwenaudio config` emits a follow-up telling the user to run
`qwenaudio gateway restart`.
