**There is no design system and no component library.** No Storybook, no styled-components, no
Tailwind, no MUI/Chakra/Ant. Styling is two hand-written stylesheets (`web/src/styles.css`,
`mobile/src/mobile.css`) plus `desktop/src/settings.css`.

For a project of 985 files this is a deliberately small UI surface — the product is a voice runtime
with an orb, not a screen-heavy application.

### The orb pair

`DesktopSpriteOrb` and `DesktopFluidOrb` are alternatives, not siblings in a hierarchy. `App.jsx`
holds `spriteOrbFailed` state and falls back from sprite to fluid when a skin manifest fails to
load — a missing or broken skin degrades the orb rather than blanking it.

### The convention

> **New behavior goes into a pure module with a test, not into a `useEffect` or a new branch inside
> `App.jsx`.**

This is what lets 19 test suites cover the web client with no DOM harness, and it is the single most
important convention to preserve when adding features here.

## Cross-part shared modules (`shared/`, 43)

The genuinely reusable layer — importable by any client, including third-party ones. Grouped in
[`architecture-clients.md`](./architecture-clients.md#shared--the-contract-layer-). The
UI-relevant members:

| Module | Used by | Provides |
| --- | --- | --- |
| `gateway-client-state.mjs` | web (`useReducer`), tui (direct calls) | The pure protocol-state reducer |
| `gateway-client-sdk.mjs` | web, tui | `GatewayClient` |
| `client-input-capabilities.mjs` | web, tui | `clientInputCapabilities`, `supportsComposerInput` |
| `gateway-client-profiles.mjs` | web, tui | `gatewayReferenceClientCapabilities` |
| `orb-skin-catalog.mjs` | web, desktop, server | Skin id validation and built-in catalog |
| `citation-display.mjs` | tui | `formatCitationLines` |
| `input-parts.mjs` | tui, server | Input part construction |

**A "component" reused across clients belongs in `shared/`, not duplicated per part** — which is why
`gateway-client-state.mjs` lives there rather than in `web/src/`.

## Desktop main-process modules (44)

Not UI components, but the reusable units of the desktop part. Eight are published through
`exports` (`./orb/main`, `./orb/window`, `./orb/placement`, `./orb/presence`, `./orb/preload`,
`./orb/url`, `./settings`, `./skin-store`) — meaning an **embedding host can reuse the orb shell**
without the rest of the app. Full map in
[`frontend-architecture-desktop.md`](./frontend-architecture-desktop.md).
