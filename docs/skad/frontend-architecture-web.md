## State management

**There is no state library.** No Redux, MobX, Zustand, or Context provider tree. State is held in
three tiers, and knowing which tier owns a value is the main thing to get right when editing here.

### Tier 1 — Protocol state: a pure reducer in `shared/`

The one piece of genuinely shared, testable state lives outside the web app entirely, in
`shared/gateway-client-state.mjs`, and is driven by `useReducer` in `useRealtimeVoice.js:223`.

```
createGatewayClientState() -> {
  connectionState: 'connecting' | 'connected' | 'unavailable',
  voiceReady:      boolean,
  voiceState:      'idle' | ...,
  wakeWordActive:  boolean,
  ownership:       { state: 'available' | 'busy', holder: string | null },
  currentTurnId:   string,
}
```

`reduceGatewayClientState(state, event)` is a **pure function of Gateway server events** and handles
exactly nine event types: `GATEWAY_CONNECTED`, `GATEWAY_DISCONNECTED`, `VOICE_READY`,
`VOICE_CONNECTION`, `TURN_STARTED`, `VOICE_STATE`, `VOICE_SLEEP`, `VOICE_OWNERSHIP`,
`VOICE_DEACTIVATED`. Everything else returns `state` unchanged.

Because it is pure and lives in `shared/`, **every Gateway client reuses it** — the web app, and
anything else built on the client SDK. Protocol state transitions belong here, not in a component.

#### Two guards that are easy to break

- **`VOICE_READY` is ignored without `inputSampleRate`.** A ready event lacking a sample rate is
  dropped, not treated as ready.
- **Stale-turn rejection.** `acceptsGatewayVoiceState(event, currentTurnId)` drops a `VOICE_STATE`
  event whose `turnId` is set, differs from the current turn, *and* has `origin === 'model'`. This
  is what stops a late event from a superseded turn repainting the orb. Non-model-origin events
  (user actions) are always accepted.

`App.jsx` (1,503 LOC) holds **26 `useState` hooks** — the app's session-scoped state. Grouped:

`App.jsx` is the single composition root: there is no prop-drilling avoidance mechanism, and child
components receive plain props.

### Tier 3 — Imperative state: `useRef` in `useRealtimeVoice.js`

`useRealtimeVoice.js` (1,024 LOC) keeps **~20 refs** for values that must not trigger re-render:
the socket (`socketRef`), the `AudioContext` (`audioRef`), callback mirrors
(`eventRef`/`inputErrorRef`/`clientActionRef`/`wakeWordAudioRef`, reassigned every render), and the
audio scheduling ledger `playbackRef`:

```
playbackRef.current = {
  cursor, sources[], startTimers: Map, endTimers: Map, responseEnds: Map,
  startedResponses: Set, sourceCounts: Map, doneResponses: Set, failedResponses: Set,
}
```

**This is the highest-risk object in the web client.** It tracks per-response audio scheduling
across Web Audio callbacks; the `Set`/`Map` members exist to make playback start/end idempotent
under out-of-order events. Mutating it from a component, or converting it to `useState`, will
desynchronize playback receipts from the Gateway.

`clientInstanceId` is a `crypto.randomUUID()` generated once per hook instance and is how the
Gateway distinguishes two tabs of the same session for ownership/takeover.

### Orb rendering strategy

Two orb implementations coexist. `spriteOrbFailed` state in `App.jsx` falls back from
`DesktopSpriteOrb` to `DesktopFluidOrb` when a skin manifest fails to load, so a broken or missing
skin degrades rather than blanking the orb. Skin identifiers are validated against
`shared/orb-skin-catalog.mjs`.

## Internationalization

`i18n.js` uses an unusual convention: **`t()` takes the Simplified Chinese string as the key** —
`t('当前浏览器不支持实时语音播放')` — and translates *outward* to the runtime language set by
`setRuntimeLanguage()`. New user-facing strings must be added as Chinese source text, not English.
