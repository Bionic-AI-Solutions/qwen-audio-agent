## 1. Entry points

| Kind | Path | Notes |
| --- | --- | --- |
| npm binary | `cli/bin/qwenaudio.mjs` | The only `bin` — installs as `qwenaudio` |
| Gateway boot | `server/src/app/bootstrap.mjs` | Composes and starts the application |
| Gateway app | `server/src/app/gateway-application.mjs` | Express app + all 28 route registrations |
| Web SPA | `web/src/main.jsx` | Mounts `App` |
| Mobile shell | `mobile/src/main.jsx` | Pairing shell; lazily imports the web `App` |
| Desktop main | `desktop/src/main.mjs` | Electron main process (1,674 LOC) |
| Desktop preload | `desktop/src/preload.cjs` | The complete IPC contract |
| Launcher | `scripts/start.mjs` | `npm start` / `npm run backend` |

**The root package has no `main`.** Consumers enter exclusively through the `exports` map.

## 2. The published API surface — 42 `exports` entries

This is the single most important architectural fact for anyone changing code here.

**`package.json#exports` publishes 42 named entry points, and they reach into every workspace** —
not just `shared/`. Roughly:

| Group | Count | Examples |
| --- | --- | --- |
| Gateway protocol & events | 10 | `./gateway-protocol`, `./gateway-client-protocol`, `./realtime-events`, `./gateway-events`, `./ag-ui-events`, `./session-events` |
| Client SDK & profiles | 5 | `./gateway-client-sdk`, `./gateway-client-profiles`, `./gateway-client-state`, `./conversation-history` |
| Remote access & auth | 6 | `./gateway-remote-access`, `./gateway-access-client`, `./gateway-websocket-auth`, `./gateway-file-credential-store`, `./gateway-connection-profiles`, `./gateway-endpoint-publishers` |
| Extension SDKs | 5 | `./backend-adapter-sdk`, `./a2a-backend-adapter`, `./realtime-provider`, `./memory-provider`, `./knowledge-provider` |
| Server internals | 6 | `./gateway-application`, `./client-events`, `./client-actions`, `./agent-delivery`, `./session-journal`, `./session-replay` |
| Desktop / orb | 8 | `./orb/main`, `./orb/window`, `./orb/placement`, `./orb/presence`, `./orb/preload`, `./orb/url`, `./settings`, `./skin-store` |
| Process & lifecycle | 4 | `./gateway-process`, `./gateway-setup`, `./gateway-lease`, `./electron` |
| Build output | 1 | `./web-dist/*` |

### The consequence

> **A file reachable through `exports` is public API, wherever it lives.**

`server/src/app/gateway-application.mjs`, `desktop/src/settings-store.mjs`, and
`server/src/session/session-journal.mjs` are *not* internal modules — they are published. Renaming
an export, changing a signature, or moving one of these files is a **breaking change for
third-party extensions**, even though the path looks internal. Conversely, anything **not** in the
map is genuinely internal and may change freely.

## 3. Configuration

### Environment variables — 72, two prefixes

| Prefix | Count | Meaning |
| --- | --- | --- |
| `QWEN_AUDIO_AGENT_*` | ~64 | Runtime configuration |
| `QWAUDIO_*` | ~8 | Paths and **error codes** |

Note the `QWAUDIO_*` prefix is overloaded: `QWAUDIO_CONFIG_DIR` and `QWAUDIO_DATA_DIR` are real

`QWAUDIO_INPUT_OWNER_REQUIRED` are **`error.code` values**, not settings. Don't add them to a config
file.

## 4. Authentication and security

### Design principle

> **Local access is zero-config. Remote access requires a credential. Secrets never travel inside
> Gateway Client Protocol messages.**

### Modules

| Module | Role |
| --- | --- |
| `server/src/access/gateway-access.mjs` | `GatewayDeviceRegistry` — paired devices, tokens stored as **hashes** |
| `server/src/access/browser-pairing-page.mjs` | The `GET /connect` HTML shell |
| `server/src/core/work-authorization.mjs` | Authorization for task/work execution |
| `shared/gateway-websocket-auth.mjs` | Credential → WebSocket subprotocol |
| `shared/gateway-access-client.mjs` | Client-side access flow |
| `shared/gateway-file-credential-store.mjs` | On-disk credential storage |
| `shared/gateway-remote-access.mjs` | Invitation encode/decode + zod schemas |
| `desktop/src/security.mjs` | URL validation for the Electron shell |
| `desktop/src/gateway-credential-store.mjs` | Desktop credential storage |

### Transport rules, enforced in code

| Rule | Where |
| --- | --- |
| Credentials ride as a **WebSocket subprotocol**, never a query parameter | `gatewayWebSocketProtocols` |
| A credential + non-`wss:` socket **throws** | `web/src/gateway-transport.js#createGatewayWebSocket` |
| Over HTTP the credential is an `Authorization: Bearer` header | `gatewayFetch` |
| A Gateway URL must be a bare **origin** (no path/query/fragment/userinfo) | `cleanGatewayUrl`, `parseMobileGatewayProfile` |
| Electron: `https:` only, or `http:` on loopback | `security.mjs#validateAppUrl` |
| Mobile: `https:` only, checked at pairing **and** at profile load | `mobile-profile.js` |
| The pairing invitation stays in the **URL fragment**, so it never reaches a request or access log | `GET /connect` |
| `POST /api/access/pair` is the **only** unauthenticated remote operation, guarded by an origin allowlist | `gateway-application.mjs:554` |
| Device tokens are **revocable per device** | `DELETE /api/access/devices/:id` |

### Middleware order in `gateway-application.mjs`

The ordering is deliberate and fragile — `/connect` and `/api/access/pair` are registered
**before** `enforceSameOrigin` and the auth middleware (line 583–599), because they must be
reachable pre-authentication. Everything registered after those lines is authenticated. **Adding a
route above line 598 silently makes it public.**

### Electron hardening

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` on every window;
`setWindowOpenHandler` denies all popups; `will-navigate` is prevented; `openExternal` is gated by
`isSafeExternalUrl`. See [`frontend-architecture-desktop.md`](./frontend-architecture-desktop.md).

### Dependency governance

Six transitive `overrides` pin patched versions (`@xmldom/xmldom` 0.8.15, `@hono/node-server`
2.0.12, `@electron/asar` 4.2.1, `@electron/universal` 3.0.6, `fast-uri` 3.1.6, `qs` 6.16.0), and
`npm run audit:release` (`scripts/audit-dependencies.mjs`) gates releases.

## 5. Async and event-driven architecture

The system is **event-driven over a WebSocket**, not request/response over REST. Three event
vocabularies coexist:

| Vocabulary | Module | Size |
| --- | --- | --- |
| Gateway realtime events | `shared/realtime-events.mjs` | 15 client→server, 22 server→client |
| Gateway task events | (task event enum) | 20 |
| Gateway Client Protocol v6 | `shared/gateway-client-protocol.mjs` | 26 zod envelope schemas |
| AG-UI projection | `shared/protocol/agui-events.mjs` | Exposed via `?format=ag-ui` |
| Session events | `shared/session-events.mjs` | Journal/replay |

Supporting machinery: `server/src/client/client-event-router.mjs` (routing),
`server/src/delivery/agent-delivery.mjs` (delivery), `server/src/session/session-journal.mjs` +
`session-replay.mjs` (durable event log and bounded replay), `server/src/task/` (async work).

Concurrency and backpressure are configured rather than hard-coded — see the task/announcement
environment groups above. Announcements batch (`_BATCH_MS`), respect a quiet period
(`_QUIET_MS`), require acknowledgement (`_ACK_TIMEOUT_MS`), and retry a bounded number of times
(`_MAX_RETRIES`).

Worker threads are used where blocking would hurt: `desktop/src/backend-detection-worker.mjs` and
`desktop/src/wake-word/worker.mjs`.

## 6. CI/CD

Four GitHub Actions workflows. All four declare `permissions: contents: read`, use
**SHA-pinned actions**, `persist-credentials: false`, and a `concurrency` group.

| Workflow | Trigger | Jobs |
| --- | --- | --- |
| `ci.yml` | push to `main`, all PRs | `test` matrix — {ubuntu, macos, windows} × Node {22.22.2, 24.15.0}, `fail-fast: false` (6 combinations); plus release-check |
| `docs.yml` | path-filtered: `docs/**`, `sync-docs-site.mjs`, manifests | VitePress build |
| `mobile.yml` | path-filtered: `mobile/**`, `web/**`, `shared/**` | `android` (ubuntu), `ios` (macos) |
| `release.yml` | push to `main` touching `CHANGELOG.md` or any `package.json`; or `workflow_dispatch` | plan → verify → tag → npm publish → macOS/Windows/Linux artifacts. `cancel-in-progress: false` |

`mobile.yml` correctly triggers on `web/**` — because mobile embeds the web client, a web change is
a mobile change.

Release is **changelog-driven**: publishing is triggered by committing a version bump plus
`CHANGELOG.md`, with `workflow_dispatch` available to recover or re-publish an existing version.

### Test topology

`node --test` everywhere — no Jest, Vitest, or Mocha. The root `npm test` runs, in sequence:
root `test/*.test.mjs` → server → web → tui → desktop → cli → mobile → smart-cockpit → voicemem.
Example suites install their own dependencies via a `pretest:smart-cockpit` hook using
`npm ci --ignore-scripts`.

`npm run eval:frontend` (`server/eval/run-frontend-evaluations.mjs`) is a separate evaluation
harness, not part of `npm test`.

## 7. Internationalization

Bilingual throughout: **English + Simplified Chinese**.

### The `t()` convention — Chinese is the key

Both `web/src/i18n.js` and `desktop/src/i18n.mjs` use the **Simplified Chinese string as the
lookup key**:

```js
t('当前浏览器不支持实时语音播放')
```

New user-facing strings must be authored in Chinese and translated outward. This extends to
filenames — `desktop/src/assets/icons/` contains `删除.svg`, `设置.svg`, `重试.svg`, etc.

Source comments are mixed Chinese and English, sometimes within one file.

### Documentation parity is enforced

`docs/i18n-parity.md` documents a parity rule between `*.md` and `*.zh.md`, and
`scripts/sync-docs-site.mjs` runs as a `pre` hook on **every** `docs:*` script (`predocs:dev`,
`predocs:build`, `predocs:preview`). 59 English pages have `.zh.md` mirrors.

> **Any new file under `docs/` joins the VitePress site and participates in parity checks.** This is
> why SKAD output lives in `docs/skad/` and must be excluded from the VitePress build — see the
> Deployment Guide.

Runtime language reaches the desktop orb as a `lang` query parameter via `desktopOrbUrl`, and the
web client applies it through `setRuntimeLanguage()`.
