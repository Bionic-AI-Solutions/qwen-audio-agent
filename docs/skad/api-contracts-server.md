**Stability rule stated in the source:** minor bump for an additive capability, major bump for a
breaking change to any endpoint or event named in `GATEWAY_CAPABILITIES`. Clients must branch on a
**capability string**, never on a product version. Anything not listed in `GATEWAY_CAPABILITIES` is
internal and may change in any release. Every listed capability is locked by a test.

## WebSocket event vocabulary

Defined in `shared/realtime-events.mjs`. This is the **replaceable Conversation Client boundary**
(capability `realtime.conversation-client-v1`) — any client implementing these events is a
first-class client.

### Client → Server (`GatewayClientEvent`, 15)

`connect`, `unmute`, `mute`, `input.unmute`, `input.mute`, `audio.append`, `text.message`,
`input.message`, `interrupt`, `sleep`, `wake`, `playback.started`, `playback.ended`,
`playback.cancelled`, `input.suspend.ack`

> Note on `input.suspend.ack`: the source explicitly says a host **must not wait** for it —
> push-to-talk is latency sensitive, so the ack only feeds status display and timeout healing.

### Server → Client (`GatewayServerEvent`, 22)

`gateway.connected`, `gateway.disconnected`, `voice.connection`, `voice.ready`, `voice.state`,
`voice.ownership`, `voice.deactivated`, `voice.sleep`, `turn.started`, `playback.clear`,
`input.suspend`, `input.resume`, `audio.delta`, `audio.done`, `response.started`,
`response.interrupted`, `transcript.delta`, `transcript.final`, `transcript.discard`, `tool.call`,
`agent.activity`, `client.state`, `error`

> `input.suspend` is stronger than the client-declared `input.mute`: no capture, no wake-word
> detection.

### Task events (`GatewayTaskEvent`, 20)

Lifecycle: `task.snapshot`, `task.accepted`, `task.scheduled`, `task.scheduled.fired`,
`task.running`, `task.delegated`, `task.finalizing`, `task.cancelling`, `task.updated`,
`task.progress`, `task.completed`, `task.failed`, `task.cancelled`

Interaction: `task.permission.requested`, `task.permission.resolved`, `task.input.requested`,
`task.input.resolved`

Notification: `task.notification.pending`, `task.notification.delivered`, `task.notification.offline`

Task states are A2A-aligned (`submitted` / `working` / `auth_required`) — capability
`tasks.structured-results-authorization`. Every public task carries one short `id`
(`task_id` in model tool results) — capability `tasks.unified-id-updates`.

## Gateway Client Protocol v6 (GCP6) — WebSocket runtime commands

Defined in `shared/gateway-client-protocol.mjs`, version **6.0.0**. Opt-in via handshake; all 5.x
event names remain compatibility aliases through one normalization layer.

### Handshake — capability `...v6-handshake`

| Event | Direction |
| --- | --- |
| `session.hello` | client → server |
| `session.ready` | server → client |
| `session.output_voice.update` / `.updated` | client → server / server → client |

Version negotiation compares a client-supplied `{min, max}` range against
`GATEWAY_CLIENT_PROTOCOL_VERSION` with semver comparison.

### Realtime aliases (normalization layer)

| GCP6 event | 5.x alias |
| --- | --- |
| `input_audio_buffer.append` | `audio.append` |
| `conversation.item.create` | `input.message` |
| `response.cancel` | `interrupt` |

### Runtime commands — capability `...v6-runtime-commands`

Every command has a matching `.result`, correlated by `request_event_id`:

| Command | Result |
| --- | --- |
| `task.create` | `task.create.result` |
| `task.get` | `task.get.result` |
| `task.list` | `task.list.result` |
| `task.cancel` | `task.cancel.result` |
| `permission.respond` | `permission.respond.result` |
| `task.input.respond` | `task.input.respond.result` |
| `conversation.history` | `conversation.history.result` |
| `session.replay` | `session.replay.result` |
| `client.event.publish` | `client.event.publish.result` |

These migrate first-party task/history/permission recovery onto the WebSocket; the REST paths above
remain as migration aliases.

### Client Actions — capability `...v6-client-actions`

| Event | Direction |
| --- | --- |
| `client.action.request` | server → client |
| `client.action.result` | client → server |

Gateway-to-Client environment operations use correlated request/result. `enter_sleep` is
capability-gated: the Gateway commits to sleeping **only after** the active client reports a
successful transition.

### Ownership and replay

- **Owner takeover** (`...v6-owner-takeover`): active-client ownership is scoped by authenticated
  owner; a negotiated client may explicitly replace that owner's current client. Monotonically
  increasing **lease generations** fence late messages and stale releases.
  Implemented in `server/src/client/active-client-leases.mjs`.
- **Replay** (`...v6-reference-client-replay`): replayable task pushes carry monotonic sequence
  numbers; `session.replay` returns a bounded page after a cursor. Buffer in
  `server/src/transport/gateway-client-replay-buffer.mjs`.

## Schemas (zod)

Declared in `shared/protocol/gateway-events.mjs`:

`GatewayEventEnvelopeSchema`, `GatewayArtifactPartSchema`, `GatewayArtifactSchema`,
`GatewayCitationSchema`, `GatewayAuthorizationSchema`, `GatewayInputRequestSchema`,
`GatewayActivitySchema`, `GatewayTaskSchema`, `GatewayInputPartSchema` (discriminated union on

`GatewayServerMessageSchema`.

Parse entry points: `parseGatewayClientMessage(value)`, `parseGatewayServerMessage(value)`.

Two enforced invariants worth knowing:
- an input message requires **either** `text` **or** `parts` ("a text or parts payload is required");
- **citations are allowed only on final assistant transcripts** — capability `messages.citations`.

## Authentication

- **Local:** zero-config, no credential required.
- **Remote:** configured credential or a paired device token
  (`shared/gateway-websocket-auth.mjs`, `shared/gateway-access-client.mjs`,
  `shared/gateway-file-credential-store.mjs`).
- Pairing tokens are revocable per device and are never transported inside GCP messages.
