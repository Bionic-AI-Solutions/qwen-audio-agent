## Running it

| Command | What it does |
| --- | --- |
| `npm run dev` | Server + web concurrently (`concurrently -n server,web`) |
| `npm start` | `scripts/start.mjs` — the launcher |
| `npm run gateway` | Build web, then start the Gateway (`pregateway` → `npm run build`) |
| `npm run backend` | Same as `npm start` |
| `npm run desktop` | Electron app |
| `npm run tui -- <args>` | Terminal client |
| `npm run cli -- <args>` | `qwenaudio` CLI |
| `npm run openclaw` / `npm run opencode` | Adapter harnesses (`scripts/*.mjs`) |

`npm run gateway` has a `pregateway` hook that builds `web/` first — the Gateway serves
`web/dist`, so starting it without a build yields a 404 catch-all.

## Testing

**`node --test` only.** No Jest, Vitest, or Mocha anywhere.

`npm test` runs eight suites in sequence:

```
test/*.test.mjs  →  server  →  web  →  tui  →  desktop  →  cli  →  mobile
                 →  test:smart-cockpit  →  test:voicemem
```

| Command | Scope |
| --- | --- |
| `node --test test/*.test.mjs` | Cross-part integration tests (33 files) |
| `npm test --workspace server` | Server suites |
| `npm test --workspace web` | 19 web suites (no DOM harness — pure modules only) |
| `npm run test:smart-cockpit` | Example; `pretest` hook runs `npm ci --ignore-scripts` in its subprojects |
| `npm run test:voicemem` | VoiceMem example |
| `npm run test:desktop-smoke` | `scripts/electron-smoke.mjs` — **not** part of `npm test` |
| `npm run eval:frontend` | `server/eval/run-frontend-evaluations.mjs` — **not** part of `npm test` |

Test file convention: `*.test.mjs` in a `test/` directory beside the code.

### Where to add a test

The web part's convention is 1:1 — `web/src/foo.js` has `web/test/foo.test.mjs`. Logic is pushed
into pure modules specifically so it can be tested without a browser. Follow that rather than
reaching for a DOM harness.

`eslint-plugin-react-hooks` 7.1.1).

Ignored paths — **code here is not linted**:

**/node_modules/**   **/dist/**   **/coverage/**

## Configuration

Copy `.env.example` (6 KB, 55 documented variables, **only 2 uncommented by default**) and fill in
what you need.

| Group | Variables |
| --- | --- |
| **Required for default setup** | `DASHSCOPE_API_KEY` — Qwen Audio Realtime is the default voice frontend |
| Voice / realtime | `QWEN_AUDIO_REALTIME_MODEL`, `_PROVIDER`, `_VOICE`, `QWEN_OMNI_REALTIME_VOICE`, `SPEECH_TO_SPEECH_REALTIME_URL` |
| Web search | `QWEN_AUDIO_WEB_SEARCH_PROVIDER` (default: keyless Bing HTML adapter; `bailian` or `none` also valid), `_MCP_URL`, `_MCP_TOKEN`, `_MCP_TOOL` |
| Features | `QWEN_AUDIO_DOMAIN_LIBRARY`, `QWEN_AUDIO_PREFERENCE_LEARNING`, `QWEN_AUDIO_SESSION_DIGEST` |
| Gateway | `QWEN_AUDIO_AGENT_BACKEND_AGENT`, `_BACKEND_MODEL`, `_BACKEND_PERMISSION_MODE`, `_ALLOWED_ORIGINS` |
| Backend agents | Per-adapter blocks for Claude Code, Codex, Qwen Code, OpenClaw, OpenCode, CodeBuddy, Kimi, Pi, Hermes, Qoder, and generic ACP (`ACP_COMMAND`, `ACP_ARGS`, `ACP_WORKSPACE`, `ACP_LABEL`, `AGENT_PROTOCOL`) |

Note the **three distinct prefixes** — `DASHSCOPE_*`, `QWEN_AUDIO_*` (feature flags), and
`QWEN_AUDIO_AGENT_*` (Gateway runtime). They are not interchangeable. The full 72-variable runtime
set is catalogued in [`cross-cutting-concerns.md`](./cross-cutting-concerns.md); `.env.example`
documents the 55 a user is expected to touch.

Harness configs for specific backends live in `config/`: `frontend-agent`, `openclaw`,
`deepseek-harness`.

> **`CONTRIBUTING.md` rule:** every new configuration option must have a **safe default**, and must
> be added to both `.env.example` and the configuration docs in the same change.

## Deployment

**There is no container or cloud deployment.** The scan found no `Dockerfile`, `docker-compose.yml`,
`k8s/`, `helm/`, `terraform/`, or `pulumi/`. This is deliberate: the Gateway is a **local process on
the user's own machine**, and remote access is reached by tunnelling to it rather than by hosting
it.

| Distribution channel | Mechanism |
| --- | --- |
| npm | `qwen-audio-agent` package, published with **provenance**; `qwenaudio` binary |
| macOS | Universal DMG, Developer ID signed + Apple notarized, attached to the GitHub Release |
| Windows / Linux | electron-builder artifacts (`--win --x64`, AppImage + deb) |
| Mobile | Built in CI; not published to app stores from this repo |
| Docs site | VitePress → GitHub Pages via `docs.yml` |
| Remote access | **Tailscale HTTPS** to the user's own Gateway (`shared/gateway-tailscale-publisher.mjs`); mobile refuses anything but `https:` |

### Documentation site — the constraint to respect

`scripts/sync-docs-site.mjs` runs as a `pre` hook on **every** `docs:*` script, and
`docs/i18n-parity.md` enforces `*.md` ↔ `*.zh.md` parity.

> **Any new file under `docs/` joins the VitePress site and participates in parity checks.**
> `docs/skad/` is SKAD scan output — English-only, internal, and not part of the published site. It
> must be excluded from the VitePress build, or `npm run docs:build` will fail parity and the
> internal artifacts will publish.

## Contribution rules

From `CONTRIBUTING.md` (the document is written in Simplified Chinese):

### Change principles

- **Preserve the boundary between the Realtime frontend and the background Agent.** Follow
  `docs/architecture/deep-dive.md` — this is the core architectural invariant.
- A fix must include a test covering the failing scenario.
- Do not reorder or rewrite large blocks of code in an unrelated change.
- New configuration needs a safe default plus updates to `.env.example` and the config docs.
- User-visible behavior changes update `CHANGELOG.md`.

### Never commit

`.env`, API keys, user profiles, task state, logs, or backend working directories.

### Pull requests

State the problem, the fix, the verification commands, and compatibility impact. Changes touching
**networking, permissions, persistence, process management, or release** must additionally spell out
security implications and the rollback path.

## Release process

**The root `package.json` version is the single source of truth.**

```bash
npm run version:patch                # 0.5.0 → 0.5.1   compatible fixes
npm run version:minor                # 0.5.0 → 0.6.0   compatible features
npm run version:major                # 0.5.0 → 1.0.0   breaking / stable
npm run version:set -- 0.6.0-beta.1  # explicit prerelease
```

`scripts/set-version.mjs` syncs the root package, every workspace, and `package-lock.json`.

Then update `CHANGELOG.md` and run `npm run release:check`, which verifies:

1. the root version is valid semver;
2. **all seven manifests match it** — root, server, web, tui, desktop, cli, mobile;
3. `README.md` and `README_ZH.md` use the dynamic npm badge.

`npm run audit:release` (`scripts/audit-dependencies.mjs`) is the dependency gate;
`overrides` pin six patched transitive dependencies.

### Pipeline

Release work goes on a dedicated branch (`release/0.11.0` or `codex/release-0.11.0`). When the
release PR merges to `main`, `release.yml` confirms the version actually changed, that a matching
CHANGELOG entry exists, and that checks pass — then tags `v0.11.0`, publishes to npm with
provenance, builds the Universal macOS app, signs and notarizes it, and uploads the DMG to the
GitHub Release.

**A normal PR merge, or a `main` update that does not change the version, publishes nothing.**

### Recovering a partial release

If a release breaks between tagging, npm upload, and Release creation, re-run the Release workflow
manually from GitHub Actions with the current `package.json` version as input — **completed stages
are safely reused**.

### Required repository secrets

`NPM_TOKEN`, `CSC_LINK` (Base64 `.p12` with certificate + private key), `CSC_KEY_PASSWORD`,
`APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`.

## CI reference

| Workflow | Trigger | What runs |
| --- | --- | --- |
| `ci.yml` | push to `main`, all PRs | 6-way matrix {ubuntu, macos, windows} × Node {22.22.2, 24.15.0}, `fail-fast: false`, plus release-check |
| `docs.yml` | `docs/**`, `sync-docs-site.mjs`, manifests | VitePress build (Node 22.22.2) |
| `mobile.yml` | `mobile/**`, **`web/**`**, `shared/**`, manifests | Android on ubuntu, iOS on macos |
| `release.yml` | `main` + version/CHANGELOG change, or `workflow_dispatch` | plan → verify → tag → npm → platform artifacts |

All four use `permissions: contents: read`, SHA-pinned actions, `persist-credentials: false`, and a
concurrency group. Only `release.yml` sets `cancel-in-progress: false`.
