# Contribution Guide

> Generated by SKAD `document-project` step 9 (deep scan) on 2026-09-05.
> Derived from `CONTRIBUTING.md`, `eslint.config.mjs`, `.github/pull_request_template.md`,
> and observed repository conventions. `CONTRIBUTING.md` is authoritative and written in
> Simplified Chinese; this file records the enforced conventions in English for AI agents.

## The five change principles

Straight from `CONTRIBUTING.md`, in priority order:

1. **Preserve the boundary between the Realtime frontend and the background Agent**, per
   `docs/architecture/deep-dive.md`. This is the core architectural invariant — see
   [`architecture-server.md`](./architecture-server.md#the-architectural-boundary-that-governs-everything).
2. **A fix must include a test covering the failing scenario.** Not a test that the fix works — a
   test that reproduces the bug.
3. **Do not reorder or rewrite large blocks of code in an unrelated change.** Keep diffs reviewable.
4. **New configuration must have a safe default**, and must update `.env.example` *and* the
   configuration docs in the same change.
5. **User-visible behavior changes update `CHANGELOG.md`.**

## Never commit

`.env` files, API keys, user profiles, task state, logs, or backend working directories.

The PR template makes this a checkbox: *"No secrets, user data, logs, or internal addresses
committed."*

## Code style

There is no Prettier and no formatter. Style is enforced by ESLint plus the conventions visible in
the code.

### Observed conventions

| Convention | Detail |
| --- | --- |
| Modules | ESM everywhere; `.mjs` for Node code, `.jsx` for React, `.cjs` only where required (Electron preload, `electron-host.cjs`) |
| Semicolons | **None** |
| Quotes | Single |
| Indentation | 2 spaces |
| Trailing commas | Yes, in multiline literals |
| Naming | `camelCase` functions/variables, `PascalCase` classes/components, `SCREAMING_SNAKE_CASE` module constants |
| Immutability | `Object.freeze()` for exported constant tables and policies |
| Privacy | `#private` class fields (e.g. `TaskRepository.#serializedRecords`) |
| Comments | Explain **why**, not what. Mixed English and Chinese, sometimes in one file |
| User-facing strings | Simplified Chinese — it is the `t()` lookup key |

### ESLint rules (`eslint.config.mjs`, flat config, ESLint 10.8.0)

A deliberately small correctness-focused set — 14 rules, no stylistic rules:

```
no-constant-condition (checkLoops: false)   no-dupe-else-if      no-fallthrough
no-irregular-whitespace                     no-loss-of-precision no-self-assign
no-unreachable                              no-unsafe-finally    no-useless-catch
no-useless-escape                           no-with              valid-typeof
no-unused-vars  { argsIgnorePattern: '^_', varsIgnorePattern: '^_', caughtErrors: 'none' }
```

**Prefix an intentionally unused binding with `_`.** Caught errors are exempt, which is why
`catch { }` blocks appear throughout — the codebase uses empty catches deliberately (diagnostics
must never break startup) and ESLint permits it.

### Scoped overrides

| Scope | Rule |
| --- | --- |
| `**/*.cjs` | `sourceType: 'commonjs'` |
| `**/test/**` | `no-useless-escape` off — regex-heavy test fixtures |
| `web/src/**`, `mobile/src/**` | `react-hooks/rules-of-hooks` **error**, `react-hooks/exhaustive-deps` **error** |

> `exhaustive-deps` is an **error**, not a warning. Suppressing it is not the normal path — this is
> why `useRealtimeVoice.js` mirrors callbacks into refs (`eventRef.current = onEvent`) instead of
> adding them to dependency arrays.

### The mobile import firewall

```js
// eslint.config.mjs — mobile/src/**
'no-restricted-imports': ['error', { patterns: [{
  group: ['../../server/**', '../../../server/**',
          '../../desktop/**', '../../../desktop/**'],
  message: 'Mobile must use public Gateway Client and web presentation boundaries',
}]}]
```

**Mobile may import `web/` and `shared/`, but never `server/` or `desktop/`.** This is a lint-enforced
architectural rule, not a guideline. It keeps mobile on the public client contract.

### Not linted at all

`examples/**`, `tui/native/**`, `**/dist/**`, `**/coverage/**`, `docs/.vitepress/cache|.site/**`,
and the two `mobile/**/public/**` directories holding synced web output.

## Testing requirements

| Rule | Detail |
| --- | --- |
| Runner | `node --test` only — no Jest, Vitest, or Mocha |
| Location | `test/` beside the code being tested |
| Naming | `*.test.mjs` (a few `.test.js`) |
| Web convention | 1:1 — `web/src/foo.js` ⇄ `web/test/foo.test.mjs` |
| No DOM harness | Web logic is extracted into pure modules so it can be tested without a browser |
| Capabilities | Every one of the 29 `GATEWAY_CAPABILITIES` is locked by a test |
| Adapters | New backend adapters run `backend-adapter-conformance.mjs` |

### Where to put new logic

> **Extend a pure module and add its test. Do not add a branch inside `App.jsx` or a new
> `useEffect`.**

This is the convention that makes the 19 web suites meaningful, and the same instinct applies
server-side: `desktop-surface-layout.mjs` holds geometry so it is testable without Electron;
`gateway-client-state.mjs` holds protocol state so it is testable without React.

## Pull request process

### Before opening

```bash
npm run lint
npm test
npm run build
npm run release:check
```

### PR description

`CONTRIBUTING.md` requires four things: the **problem**, the **fix**, the **verification commands**
run, and the **compatibility impact**.

The template (`.github/pull_request_template.md`) is in Chinese with three sections:

| Section | Contents |
| --- | --- |
| 变更说明 (Changes) | Problem, solution, why it is needed |
| 验证 (Verification) | Checkboxes for `npm test`, `npm run lint`, `npm run build`, plus tests for behavior changes or a stated reason none are possible |
| 兼容性与安全 (Compatibility & security) | No secrets/user data/logs/internal addresses; docs updated for config, behavior, and dependency changes; network/permission/privacy/persistence/release impact stated or marked N/A |

### Higher bar for sensitive areas

> Changes touching **networking, permissions, persistence, process management, or the release
> process** must explicitly list their **security implications and rollback path**.

Given the architecture, that covers `server/src/access/`, `server/src/core/work-authorization.mjs`,
`shared/gateway-*auth*`, all persistence stores, `desktop/src/security.mjs`, `preload.cjs`, and
anything in `scripts/` touching release.

## Commit conventions

Conventional Commits with a scope, and a trailing PR number:

```
feat(memory): support VoiceMem native audio input (#332)
feat(mobile): add shared iOS and Android client (#328)
docs(cockpit): standardize example README (#327)
feat(remote): add secure browser client transport (#325)
```

Observed types: `feat`, `docs`. Observed scopes: `memory`, `mobile`, `remote`, `cockpit`. Some older
commits use a plain imperative subject (`Add smart cockpit benchmark suite (#326)`), so the
convention is followed but not machine-enforced. Prefer the scoped form.

## The three API-compatibility traps

Documented here because none of them fail a test in this repository:

1. **`package.json#exports` is the public API — 42 entries reaching into `server/`, `desktop/`,
   `shared/`, and `web/dist`.** A file under `server/src/` can still be public. Check the map before
   renaming or resignaturing anything.
2. **`shared/` has no tests of its own.** It is covered only transitively by its consumers, and
   third-party consumers are not covered at all.
3. **Persisted-shape changes require a `fileVersion` bump.** Without it, old files are parsed as the
   new format, every record fails validation, and the store silently becomes empty — data loss with
   no error. See [`data-models.md`](./data-models.md#the-version-bump-rule).

## Documentation standards

| Rule | Detail |
| --- | --- |
| **Bilingual parity** | Every `.md` under `docs/` needs a `.zh.md` companion, or `sync-docs-site.mjs` **throws** and `npm run docs:build` fails |
| Exclusions | `EXCLUDED_DIRS` / `EXCLUDED_FILES` in `scripts/sync-docs-site.mjs` — currently `promo`, `roadmap`, `skad`, `node_modules` |
| Normative specs | `docs/gateway-protocol.md` and `docs/contract.md` — update these when the protocol changes |
| Config changes | Update `.env.example` **and** `docs/configuration/` |
| Behavior changes | Update `CHANGELOG.md` |
| Internal AI docs | `docs/skad/` — English-only, excluded from the site |

## Release contributions

Release changes go on a dedicated branch (`release/0.11.0`, `codex/release-0.11.0`), use
`npm run version:*` rather than hand-editing manifests, and require a `CHANGELOG.md` entry. See
[`deployment-guide.md`](./deployment-guide.md#release-pipeline).

## Code of conduct

Kindness, respect, and constructive collaboration are baseline requirements. Harassment,
discrimination, privacy violations, and malicious submissions are not accepted.
